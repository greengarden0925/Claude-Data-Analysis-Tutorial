# 篩檢陽性率分析（行政區 × 月份）

把一份「每列 = 某月某區」的篩檢統計，變成可查核、可重跑、分資料夾歸檔的分析成果與互動報告。
`scripts/` 內是已驗證過的程式（5 個步驟程式加 1 個共用工具），優先使用，不要從頭重寫。
適用情境：使用者上傳篩檢統計並提到篩檢陽性率、各區比較、篩檢月報、互動報告、分析成果包等。

## 適用資料

必要欄位（名稱不同時，先列出對應關係請使用者確認，再改名）：

| 欄位 | 內容 |
|---|---|
| 月份 | YYYY-MM；也接受 2025-3、2025/03、2025.3、114/03（民國年，自動加 1911） |
| 行政區 | 區名或代號 |
| 人口數 | 該區總人口（不可跨月加總；各月不同時取最新月份） |
| 篩檢人數 | 人數（整數） |
| 陽性數 | 初篩陽性人數（整數） |

其他欄位保留但不分析，報告會在限制中列出。

## 鐵則

1. **先過安全關卡，再讀資料**：使用者要**逐點**回答 (a)(b)(c)，缺一不可，只回「好」「可以」「是」不算；沒有逐點回答之前，不讀取資料內容，只能看欄位名稱（即使使用者已經先上傳檔案、或說要略過）：
   (a) 這是虛構資料，或已去識別化且單位核可使用——請使用者**用一句話說明資料來源**（例如「教學用的虛構資料」「單位核可的去識別化月報」）；
   (b) 處理非公開資料時，網路存取已關閉；
   (c) 了解成果包會含原始與逐列資料，傳遞要依單位規定。
   使用者表示資料含姓名、身分證字號、病歷號、住址等可識別資訊時，停止並建議先去識別化。
2. **先問目的再分析**：請使用者用一兩句話說明誰要用、想回答什麼。沒有目的時，用預設的三個問題：各區差多少？差異是真的還是剛好？夠不夠拿來做決定？背景只寫目的，不寫機關、人名、未公開決策。
3. **先給程式碼，等使用者回覆「執行」才執行**：凡是會讀寫資料或計算的程式都適用。寫計畫文件、建立資料夾、說明架構可以直接做。先給程式碼是為了抓分析錯誤，**不是資安檢查**。
4. **用白話溝通**：問使用者問題、回報結果、讀重點摘要時，一律用白話（例如不說「Fisher 精確檢定」「Holm 校正」「quasi-F」「φ」，而說「人數太少時改用比較保守的算法」「同時比較很多組，所以標準放嚴一點」），術語只在使用者問起時才解釋；問問題時附上建議的預設選項，讓使用者只要回答「好」。
5. **不改原始檔**；所有數字由程式算出，不自己編。
6. **用詞**：說「篩檢陽性率較高」，不說「高風險」「警示」「排名第幾」；率與人數一起呈現；顯著 ≠ 重要；建議不點名特定區有問題。
7. **缺值不補、邏輯錯誤不改**：一律排除並記錄，交給使用者決定是否回頭查。
8. **小格子**：陽性數 1–4 人的格子要提醒。真實資料的報告一律用「只含各區合計」模式；各區全期陽性數少於 5 人時，發布前要合併或遮蔽。

## 流程

### 步驟 0：安全關卡、目的、資料夾
1. 完成鐵則 1 的三點確認、鐵則 2 的目的確認。
2. 確認篩檢項目與陽性定義（檢驗方法、切點）各區、各期是否一致；不一致時先討論，不要直接比較。
3. 建立資料夾：`00_分析計畫`、`01_原始資料`、`02_清理後資料`、`03_程式碼`、`04_結果表格`、`05_圖表`、`06_報告`。
4. 原始 CSV 放進 `01_原始資料/`（裡面只能有 1 個 CSV）；把 `scripts/` 的 6 個檔案複製到 `03_程式碼/`；用 `assets/README範本.md` 建立最上層 `README.md`。
5. 用 `assets/報告設定範本.json` 建立 `00_分析計畫/報告設定.json`：**先問使用者**標題、頁首註記（篩檢項目、對象、期間、截止日）、情境，再填入。範本裡所有〔 〕都要換成實際內容，否則報告程式會停止。真實資料保持 `"報告資料細節": "只含各區合計"`、`"提供下載逐列資料": false`；只有虛構或已核可公開的資料才改成 `"逐月"`。
   「只含各區合計」模式下，全期陽性數少於門檻（預設 5）的區，報告不放進該區的陽性數與率，只顯示「< 5」，其相關兩兩比較與差值句子也不放進報告；只有 1 區被遮蔽時，會連帶多遮陽性數次少的一區，避免由「合計減其他區」反推；遮蔽後不到 2 區可呈現時程式會停止。這不是完整的去識別化，發布前仍要依單位規定確認。

### 步驟 1：體檢與清理 → `01_clean.py`
預設規則：完全重複只留一筆；行政區全形轉半形、刪除中文字旁空白、英文大寫，行政區空白視為缺值；月份轉 YYYY-MM（含民國年）；篩檢人數缺值、為 0 或不是數字就排除；人數不是整數、人口數 ≤ 0、陽性數 > 篩檢人數或負數標「待查」並排除。檔案編碼依序嘗試 UTF-8 與 Big5（台灣 Excel 常見）。
先把規則給使用者確認，使用者要不同規則就修改程式。執行後回報：原始 → 去重 → 分析用列數、各類問題筆數，並**請使用者確認清理後的行政區清單**（同一區不應出現兩種名稱）。
數字欄只接受一般數字與標準千分位（1,234）；「1,5」「1e3」「50000人」等寫法視為無法辨識並排除、記錄，不猜。若「大安」與「大安區」並存，程式會提醒可能是同一區。
程式遇到下列情況會用中文說明並停止（停止前會先寫出修正與排除紀錄）：缺必要欄位、讀不懂文字編碼、月份無法辨識（會列出列號與原值）、行政區名稱含 < 或 >、同一月份 × 行政區有多列（會列出被合併的行政區與月份原始寫法）、少於 2 區。照訊息和使用者討論後再修改。

### 步驟 2：分析計畫 → `00_分析計畫/分析計畫.md`
依 `references/分析計畫範本.md` 填寫：問題 → 方法 → 為什麼適合 → 假設 → 怎麼檢查 → 怎麼解讀，以及「不能回答的問題」。用範本的六點清單自我審查，修正後給使用者確認。

### 步驟 3：描述性統計 → `02_descriptive.py`
表1 各區（納入月數、缺的月份、人口數、篩檢人數、年化粗篩檢率、陽性數、篩檢陽性率、Wilson 95% CI）、表2 每月、表3 各區每月、圖1、圖2。人口數各月不同時會提醒並取最新月份；整月都沒有資料時，圖2 的折線會斷開，不連過去。執行後請使用者驗算 1 個數字（陽性數 ÷ 篩檢人數）。

### 步驟 4：推論性統計 → `03_inferential.py`
表4 卡方檢定（最小期望次數 < 5 時附蒙地卡羅模擬 p 值）、表5 兩兩比較（期望次數不足時自動改用 Fisher 精確檢定；差異 95% CI 用 Newcombe 法；Holm 校正）、表6 敏感度分析（行政區＋月份的二項式 GLM；φ ≤ 1 用概似比卡方，φ > 1 用 quasi-F）、表7 考慮月份後的兩兩比較（φ > 1 用 t 分配，否則用常態）。
需要 statsmodels；沒有安裝、某區陽性數為 0、或只有 1 個月時，表6、表7 會略過並說明原因，請轉告使用者。所有區陽性都是 0 時會停止（只能做描述）。最小期望次數 < 5 時，用白話建議使用者考慮合併區域。

### 步驟 5：互動報告 → `04_report.py`
讀 `報告設定.json` 與表格，產生 `06_報告/互動報告.html`（單一檔案、不連外部網路）。結構：目的 → 重點摘要 → 資料概況 → 描述 → 推論 → 如何應用 → 實務建議（可由數據支持／需進一步查證）→ 限制與方法。重點摘要、白話解讀、建議與限制都依資料自動產生（例如區數、是否顯著、期望次數、φ、缺月、跨年、未分析欄位）。產生後把重點摘要讀給使用者核對。

### 步驟 6：歸檔打包 → `05_package.py`
檢查 00–06 與 README.md、印出清單、打包 zip。各資料夾只收約定好的檔名（例如 01_原始資料只收 1 個 CSV、03_程式碼只收 01_clean～05_package 與 _common.py），隱藏檔、暫存檔、捷徑、.xlsx／.txt／.pdf 等其他檔案一律不打包，並列出沒打包的檔案給使用者確認。提醒：成果包含原始與逐列資料，真實資料依單位規定存放與傳遞，給主管通常只需要 06_報告。

## 解讀規則

詳見 `references/解讀規則.md`。

## 完成時回報

1. 資料夾清單與 zip 檔名。
2. 關鍵數字：分析用列數、整體篩檢陽性率、整體檢定結果、兩兩比較有差的對數、考慮月份後是否改變（或為何略過）。
3. 請使用者自己查核的 3 個數字（總篩檢人數、總陽性數、任一區的陽性率）。
4. 這份資料不能回答的問題，以及報告使用的資料模式（逐月或只含各區合計）。
