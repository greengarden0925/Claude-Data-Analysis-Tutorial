講師頁

此頁給講師與助教使用，不是學員講義的一部分。時間皆為依步驟內容的估算，請在正式開課前試教一次再校準。

開課前準備清單

  • 自己先跑一遍全流程並計時（必辦）：這版加入「先看程式碼再執行」與分析計畫，每一步多一來一回，實際時間尚未經試教與審查估算。
  • 互動報告範例：參考範例；分析成果包範例：瀏覽頁與 zip。示範終點、對照資料夾結構，也可當備案。
  • （選用）預錄的全流程影片，課前寄給學員；現場不再安排 5 分鐘示範，改由模組 0 的「先看終點」取代。
  • （課後用）預先產好的輸出：修正與排除紀錄、長條圖、Word 一頁摘要，另有「分析用 91 列」CSV。
  • 出口票的收集管道：聊天室或表單，一人一行。判準：修正紀錄 1 行（原值、處理方式、原因齊全）、查核 1 個數字、說出 1 個方法檢查點。
  • 時間風險：若超時，依序縮減：體檢步驟可改為「直接執行」（只讀不寫，風險低）→ 模組 2 的自我審查改講師口述 → 模組 4 的打包改課後。
  • 失敗規則：互動報告產生超過 3 分鐘或出錯一次，就請學員改開參考範例，做查核，不再重做。課前請學員做「按一下數字加 1」的小測試。

預期故障與處理 建議助教帶著這張表巡場

學員看不懂程式碼沒有程式背景只看三件事：讀哪個檔、有沒有寫回原始檔、輸出到哪個資料夾；其他請 Claude 用白話逐段解釋

無法打包 zip 或中文檔名亂碼環境限制或解壓縮工具不支援 UTF-8 檔名請 Claude 逐一提供下載連結；改用支援 UTF-8 的解壓縮工具；或下載成果包範例對照
學員收到別人傳來的 HTML 或互動頁面不明來源的檔案可能含程式碼來源不明就不要開；確認來源後才開，並可請 Claude 列出檔案的外部連線（搜尋 http 會看到 w3.org 的 SVG 宣告，屬正常；搜不到也不代表安全）；不要輸入任何資料
互動頁面數字和預期不同忘了排除缺值與待查列、Claude 自己編了數字對照 107,171／6,850／6.39% 與 H區 530／5,601；請 Claude 說明資料來源並重做
AI 回應太慢尚在等待或流量等待時間做驗算或讀判讀提醒；超過 2 分鐘改用解答檔

停點判準與助教分工

  • 停點判準：請學員在聊天室貼綠色標記、或舉手。多數人完成就往下；落後者超過 2 分鐘，改用「分析用 91 列」檔案跟上，不要為少數人停下全班。
  • 助教分工：1 人負責設定與登入問題，1 人負責上傳與檔案問題；講師只負責主線。人數少於 15 人可由講師兼任。
  • 重跑策略：某步 Claude 回得很怪時，先請學員貼出「你期待什麼」再追問，不要整段重來；整段重來最多一次。

設計取捨 為什麼這樣排

  • 為什麼從小故事開始：先有問題才選方法。故事讓學員知道「誰要用、要回答什麼」，也讓「這份資料不能回答什麼」變得自然。故事中的人物與機關皆為虛構。
  • 為什麼先看程式碼再執行：讓學員在數字產生前就能抓到錯誤（讀錯檔、覆蓋原始檔、用百分比做檢定），也讓整個分析可以重跑、可以稽核。學員不需要會寫程式，只要看三件事。
  • 為什麼請 AI 提分析計畫，再由人確認：AI 擅長列出選項，但方法對不對要由人用檢查清單判斷；重要決策另請統計專家確認。
  • 為什麼要分資料夾：原始資料永遠不動、每一步輸出到下一個資料夾，別人（包括三個月後的自己）打開就知道去哪裡找什麼。
  • 為什麼主線做互動報告：重點在前、細節收合，兼顧主管要的結論與同仁要的完整數字；Word 摘要與簡報放課後延伸。
  • 為什麼圖不標紅、依區代碼排序、縱軸固定：紅色加由高到低排序等於暗示高風險；各區縱軸自動縮放會把小分母的雜訊放大。互動圖越好看越容易讓人相信，所以提示詞明確禁止加「高風險」「排名」等詞，並要求頁首固定顯示篩檢項目、對象、期間與截止日。
  • 固定縱軸的取捨：折線縱軸全區固定 0–16%，低值區（如 B區 4–6%）的月間變化會比較看不出來。這是刻意的：避免把雜訊誤看成趨勢；要看細節請看數字與信賴區間。
  • 虛構設定：「對象＝成人」「截止日 2026-01-31、12 月已完成通報」是為了示範報表註記而設的虛構設定，資料中沒有年齡欄。學員問到時請直說。
  • 安全內容分層：課堂只口述兩點必讀（不選知道連結就能看的選項；來源不明的檔案不開、不輸入資料），其餘放課後讀。資料安全的學習成效目前只靠自評，出口票沒有驗證。
  • 為什麼講存檔與分享：官方說明指出新頁面預設私人，但分享選項有「任何有連結的人」，且 Team／Enterprise 分享對話產生的頁面時檢視者可能看到對話附件。公衛資料風險高，要在課堂上說清楚。
  • 推論統計的選擇：卡方檢定回答「是否全部相同」，兩兩比較加 Holm 校正回答「哪幾區之間有差」，考慮月份的二項式邏輯斯迴歸作為敏感度分析。D區對 F區（差 0.83 個百分點，有差）與 E區對 H區（差 0.75 個百分點，沒有足夠證據）是「顯著 ≠ 重要」的好例子。
  • 為什麼用「篩檢陽性率較高」，不用「高風險」：篩檢對象不是隨機抽樣、資料沒有年齡欄而無法年齡標準化，受檢者陽性率不等於盛行率。
  • 為什麼刻意保留一列會造成 B區約 16% 的待查資料：讓學員親眼看到沒清理的後果。
  • 給有程式背景的講師：參考範例的 tooltip 用 innerHTML 組字串，目前只放程式內部算出的數字；若改成讓學員匯入自己的資料，請先做 HTML 跳脫。
  • 尚未做、但可考慮：把題目改成單一主題（例如癌症篩檢），疫苗接種欄位現在沒有被使用，改主題需連動資料與腳本，這次沒動。

優化建議 下一次開課

🎓 教學設計

  • 課前 3 天寄「開始前檢查」連結，登入與設定問題不要佔用課堂時間。
  • 先示範再跟做，比邊講邊做穩。
  • 備一份預先產好的輸出（Word、圖、清理檔），給無法使用檔案建立功能的學員做「閱讀與查核」。

🛡 風險控管

  • 一律用虛構或已去識別化資料，並在課前說明單位規範。
  • 強調「AI 會出錯」：每個模組都有一個人工驗算點。
  • AI 工具的介面與功能更新很快，講義上的選單名稱以開課當天畫面為準。

📈 內容升級

  • 換成學員自己業務的虛構版資料（疫苗接種、環境監測、慢性病管理）。
  • 增加「連做 3 個月」版本，示範 SOP 如何省時。
  • 進階班：多資料表合併、地圖視覺化、年齡標準化、統計方法選擇。

🔁 成效追蹤

  • 課前／課後各問一題：「做一份月報平均花多久？」
  • 一週後追蹤：有幾位學員真的在工作上使用？卡在哪？
  • 收集學員的題目構想，請學員自行改寫成虛構版再提供，下次改成新範例。
