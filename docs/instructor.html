講師頁

此頁給講師與助教使用。課程拆成兩堂、各 60 分鐘。時間皆為依步驟內容的估算，請在正式開課前自己跑一遍並計時。

開課前準備清單

  • 自己先跑一遍兩堂的全流程並計時（必辦）：這版的「先看程式碼再回覆執行」每一步多一來一回，實際時間尚未經試教確認。
  • 參考範例：互動報告、分析成果包（瀏覽頁與 zip）、第二堂起點包、skill zip。
  • 自己上傳一次 skill 並試用（Customize → Skills →「+」→「+ Create skill」→「Upload a skill」，以當天畫面為準）。skill 的程式用 23 份虛構資料做過工程測試（見 repo 的 skill/tests），但還沒在 Claude 上實際試用過。
  • （選用）預錄的全流程影片，課前寄給學員。
  • 出口票的收集管道：聊天室或表單，一人一行。兩堂各有 3 項，題目見講義模組 3 與模組 8。
  • 時間風險：若超時，依序縮減：模組 2 的自我審查改講師口述 → 模組 6 的第一步改為直接看範例的架構 → 模組 7 的打包改課後。不要臨時取消「先看程式碼」，以免和工作規則衝突；真的要省時間，請學員說「這一步你可以直接執行，執行後把程式碼貼給我看」。
  • 失敗規則：互動報告產生超過 3 分鐘或出錯一次，就改開參考範例做查核。第一堂沒做完的人，第二堂用起點包接續。

停點判準與助教分工

  • 停點判準：以「停點時間到」為準，不以單一步驟等待時間為準（等 AI 回覆常超過 1 分鐘）。時間到還沒完成的人，改用備用檔案或範例跟上，不要為少數人停下全班。
  • 助教分工：1 人負責設定與登入，1 人負責上傳、檔案與接續；講師只負責主線。人數少於 15 人可由講師兼任。
  • 重跑策略：Claude 回得很怪時，先請學員說出「你期待什麼」再追問；整段重來最多一次。

設計取捨 為什麼這樣排

  • 為什麼拆成兩堂：審查者估算一堂 60 分鐘全員實作需要 66–75 分鐘。拆成兩堂後，每段都能讓學員親手做，第一堂結束時也有可帶走的成果（分析用資料與分析計畫）。
  • 為什麼從小故事開始：先有問題才選方法。故事讓學員知道「誰要用、要回答什麼」，也讓「這份資料不能回答什麼」變得自然。故事中的人物與機關皆為虛構。
  • 先看程式碼是為了抓分析錯誤，不是資安檢查：讓學員在數字產生前抓到讀錯檔、覆蓋原始檔、用百分比做檢定等錯誤，也讓分析可以重跑與稽核。安全靠的是只用虛構或已核可資料、關閉不必要的網路存取與連接器、在沙箱裡執行。學員只要看三件事；統計正確與否用白話確認提示詞問 Claude。
  • 規則 1 的例外：寫計畫、建立資料夾、說明架構可以直接做，避免學員卡在不需要確認的步驟。
  • 為什麼請 AI 提分析計畫，再由人確認：AI 擅長列出選項，但方法對不對要由人用檢查清單判斷；重要決策另請統計專家確認。
  • 為什麼要分資料夾：原始資料永遠不動、每一步輸出到下一個資料夾，別人（包括三個月後的自己）打開就知道去哪裡找什麼。成果包含原始與逐列資料，所以 README 開頭要提醒傳遞規定。
  • 推論統計的選擇：卡方檢定回答「是否全部相同」；兩兩比較加 Holm 校正回答「哪幾區之間有差」；考慮月份的二項式邏輯斯迴歸作為敏感度分析（φ ≤ 1 用概似比卡方、φ > 1 用 quasi-F），並重做兩兩比較（C區對 G區結論改變）。D區對 F區（差 0.83 個百分點，有差）與 E區對 H區（差 0.75 個百分點，沒有足夠證據）是「顯著 ≠ 重要」的好例子。
  • 率與人數一起看：率最高的是 H區、E區，陽性人數最多的是 A區、D區。報告的建議不點名特定區，資源配置一律放在「需進一步查證」。
  • 粗篩檢率：資料有區總人口，可以算粗篩檢率，但分母不是符合資格人口、也無法排除重複受檢，只能參考。
  • 圖不標紅、依區代碼排序、縱軸固定：避免暗示風險等級，也避免把小分母的雜訊放大成趨勢。
  • 虛構設定：「甲縣」「對象＝成人」「截止日 2026-01-31、12 月已完成通報」都是虛構設定，資料中沒有年齡欄。φ ≈ 0.63 明顯小於 1，是因為示範資料由程式產生、不是逐人抽樣。
  • 為什麼最後套用 skill：讓學員下次遇到同樣格式的資料，不必重貼一整套提示詞。skill 的程式就是成果包裡的程式，用 23 份不同狀況的虛構資料做過工程測試（20 份完整跑完、3 份以中文說明停止、沒有當掉）；摘要、解讀、建議與限制都依資料條件產生。skill 先過安全關卡才讀資料，真實資料的報告預設只放各區合計。官方提醒只安裝信任來源的 skill，啟用前要先審閱。
  • 給有程式背景的講師：互動報告用 innerHTML 組字串，目前只放程式算出的數字與固定文字；若改成讓使用者匯入任意資料，請先做 HTML 跳脫。

優化建議 下一次開課

🎓 教學設計

  • 課前 3 天寄「開始前檢查」連結，登入與設定問題不要佔用課堂時間。
  • 兩堂間隔不要太久，並提醒學員一律下載第一堂的 4 個資料檔（原始資料、分析用資料、修正與排除紀錄、分析計畫）。
  • 試教後依實際時間微調各模組長度。

🛡 風險控管

  • 一律用虛構或已去識別化資料，並在課前說明單位規範。
  • 強調「AI 會出錯」與「先看程式碼不是資安檢查」。
  • AI 工具的介面與功能更新很快，選單名稱以開課當天畫面為準。

📈 內容升級

  • 換成學員自己業務的虛構版資料，並調整 skill 的欄位說明。
  • 進階班：多年資料的趨勢分析、年齡標準化、地圖視覺化。

🔁 成效追蹤

  • 課前／課後各問一題：「做一份月報平均花多久？」
  • 一個月後追蹤：有幾位學員真的用了 skill？卡在哪？
