講師頁

此頁給講師與助教使用，不是學員講義的一部分。時間皆為依步驟內容的估算，請在正式開課前試教一次再校準。

預期故障與處理 建議助教帶著這張表巡場

狀況可能原因處理
找不到「Create and edit files」介面名稱或位置不同（舊版叫 Code execution and file creation）；機關帳號由管理員控制改看講師示範與預先產好的輸出檔；課後請管理員協助
上傳失敗或檔案無法讀取用 Excel 另存、編碼問題、網路重新下載原檔直接上傳；仍失敗改用「分析用 91 列」檔
Claude 回覆和講義不一樣每次回覆文字本來就會不同看「問題是否一致」，不要求文字一致
算出的數字和講義差一點沒排除缺值或待查列；新開對話沒有上下文檢查是否 91 列；對照「預期結果」兩組數字；B區若異常偏高就是沒排除待查列
新開對話後 Claude 說沒有資料不同對話不共用上下文重新上傳「分析用 91 列」
互動 Dashboard 沒出現檔案建立功能未開、方案差異列為課後延伸；看側欄 Artifacts
AI 回應太慢尚在等待或流量等待時間做驗算或讀判讀提醒；超過 2 分鐘改用解答檔

停點判準與助教分工

  • 停點判準：請學員在聊天室貼綠色標記、或舉手。多數人完成就往下；落後者超過 2 分鐘，改用「分析用 91 列」檔案跟上，不要為少數人停下全班。
  • 助教分工：1 人負責設定與登入問題，1 人負責上傳與檔案問題；講師只負責主線。人數少於 15 人可由講師兼任。
  • 重跑策略：某步 Claude 回得很怪時，先請學員貼出「你期待什麼」再追問，不要整段重來；整段重來最多一次。

設計取捨 為什麼這樣排

  • 為什麼只做 Word 摘要：60 分鐘不夠做三種交付。簡報與互動 Dashboard 放課後延伸。
  • 為什麼信賴區間由講師示範：要避免學員把「點估計高低」當結論，但自己做太耗時。示範一張圖加一句「不能只看點估計」即可。
  • 為什麼用「篩檢陽性率較高」，不用「高風險」：篩檢對象不是隨機抽樣、未做年齡標準化，受檢者陽性率不等於盛行率。
  • 為什麼刻意保留一列會造成 B區 17–18% 的待查資料：讓學員親眼看到沒清理的後果。
  • 尚未做、但可考慮：把題目改成單一主題（例如癌症篩檢），疫苗接種欄位現在沒有被使用，改主題需連動資料與腳本，這次沒動。

優化建議 下一次開課

🎓 教學設計

  • 課前 3 天寄「開始前檢查」連結，登入與設定問題不要佔用課堂時間。
  • 先示範再跟做，比邊講邊做穩。
  • 備一份預先產好的輸出（Word、圖、清理檔），給無法使用檔案建立功能的學員做「閱讀與查核」。

🛡 風險控管

  • 一律用虛構或已去識別化資料，並在課前說明單位規範。
  • 強調「AI 會出錯」：每個模組都有一個人工驗算點。
  • AI 工具的介面與功能更新很快，講義上的選單名稱以開課當天畫面為準。

📈 內容升級

  • 換成學員自己業務的虛構版資料（疫苗接種、環境監測、慢性病管理）。
  • 增加「連做 3 個月」版本，示範 SOP 如何省時。
  • 進階班：多資料表合併、地圖視覺化、年齡標準化、統計方法選擇。

🔁 成效追蹤

  • 課前／課後各問一題：「做一份月報平均花多久？」
  • 一週後追蹤：有幾位學員真的在工作上使用？卡在哪？
  • 收集學員帶來的真實題目（去識別化後），下次改成新範例。
