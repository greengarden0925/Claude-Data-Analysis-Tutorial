逐步操作

模組 0｜講師示範＋資料安全 0–8 分
🎯 目標：先看一次完整流程（5 分鐘），再用 3 分鐘學會判斷什麼資料能上傳。

  1. 講師示範（5 分鐘，學員只看不做）

    講師現場跑一遍：上傳 → 體檢 → 確認規則 → 出表 → 驗算。學員先知道終點長什麼樣子，後面操作比較不會慌。

  2. 情境題：下面欄位哪些要先處理再上傳？（1 分鐘）

    姓名、身分證字號、病歷號、住址、就診日期（精確到日）、年齡、性別、行政區。

    答案：姓名、身分證字號、病歷號、住址一定要刪除；精確日期改成月份；年齡改成年齡層；「行政區＋性別＋年齡層＋疾病」組合起來可能只剩 1–2 人，要合併或遮蔽。

  3. 先確認單位規範

    上傳前先確認：單位是否核准使用外部 AI、可用哪種帳號（個人或機關）、這份資料的分級、是否屬於研究案（需依 IRB 核定計畫與同意範圍）、資料留存與是否用於模型訓練的設定（依官方說明與單位政策確認）。用個人帳號處理公務資料前，須先取得核可。涉及個資法規的部分，請依單位法遵確認。

  4. 網路存取與提示注入

    Claude 官方說明指出，檔案建立功能在隔離的沙箱中執行，但沙箱不等於資料不離開你的電腦：上傳的內容仍會送到 Anthropic 的伺服器處理。官方也指出，若開啟網路存取，理論上有可能被檔案或網頁中的隱藏指令誘騙，把資料送到外部；關閉網路存取可避免資料送出沙箱。但連接器（MCP）不受這個開關限制，仍可能對外連線，需另外檢視。處理非公開資料時，請關閉網路存取、不要啟用不必要的連接器，並全程盯著 Claude 的操作，發現異常立刻停止。網路存取的預設值依方案而異，請自行到設定檢查；機關帳號由管理員設定。名稱與選項以官方說明與你的畫面為準。

📖 課前閱讀：去識別化與責任（課堂上不講，請自行讀完）

去識別化不等於可以隨便上傳。檢查每個格子的人數：人數很少（例如少於 5 人，門檻請依單位規定）的格子要合併或遮蔽。避免同時保留細地區、精確日期、年齡與性別。合併或遮蔽後，也要檢查總計與其他表格能不能反推出被遮蔽的數字。去識別化後仍可能被重新辨識，所以是否可以上傳，仍須經單位同意。

AI 的輸出要人工查核，責任在署名者。數字、公式、結論都要抽查。對外報告是否要揭露 AI 輔助，依單位規定；建議保留清理紀錄與提示詞，方便日後稽核。

注意：本課全程使用電腦隨機產生的虛構資料（A–H 區是代號），不代表任何真實地區或個案。
模組 1｜資料清理：從髒資料到分析用資料 8–23 分
🎯 目標：抓出資料問題、確認處理規則，輸出「分析用資料 91 列」與修正紀錄。

  1. 開新對話，上傳 CSV

    點對話框左下角的「＋」→ 上傳檔案（選單文字可能是「Add files or photos」），選 demo_fictional_screening_dirty.csv（手機同樣點「＋」；電腦也可以直接拖曳）。請直接上傳原檔，不要先用 Excel 開啟再另存。CSV 與 TSV 是官方列出的支援格式，檔案大小上限以官方說明為準。

    對話框出現檔名縮圖。

  2. 先「體檢」，不要急著修

    先讓 Claude 只回報問題，不要動資料。

    我上傳了一份【虛構】的行政區月別篩檢統計 CSV。 欄位：月份、行政區、人口數、篩檢人數、陽性數、疫苗接種人數。 請先「只檢查、不修改」，用表格列出： 1. 重複的列（列號） 2. 缺值（欄位、列號） 3. 同一個行政區的不同寫法 4. 月份格式不一致 5. 邏輯錯誤（例如陽性數 > 篩檢人數） 每一項請附證據（列號與原始值）。最後告訴我你打算用什麼規則處理，等我確認再動手。

    一張問題清單：3 筆重複、4 筆篩檢人數缺值、2 種行政區寫法（「F 區」「a區」）、2 筆月份格式（2025/5、2025/8）、1 筆陽性數大於篩檢人數。回覆文字會略有不同，但問題應一致。

  3. 確認處理規則（由你決定，不是 AI）

    處理規則如下，請照做： 1. 完全重複的列只保留一筆 2. 行政區統一為「X區」格式（去空白、大寫） 3. 月份統一為 YYYY-MM 4. 篩檢人數缺值：不要補值，也不要放進分析用資料 5. 陽性數 > 篩檢人數：不要自行修改，標記為「待查」，也不要放進分析用資料（缺值列不算待查）
    小提醒：缺值與邏輯錯誤是專業判斷。真實資料中「陽性數大於篩檢人數」常是欄位定義或登錄問題，應先回頭問承辦人，不要自己猜。

  4. 輸出檔案與修正紀錄

    請輸出： (a) 分析用資料 CSV（已排除缺值列與待查列） (b) 修正與排除紀錄表（列號、欄位、原值、處理方式、原因） (c) 處理前後列數 輸出後，請在回覆中點檔案名稱讓我下載。

    列數：99 → 去重後 96 → 排除 5 列（4 列缺值＋1 列待查）→ 分析用 91 列。回覆中點檔案名稱即可下載。完整清理檔（含被排除的列）可課後再要。

  5. 停點：對答案

    你的分析用資料應該是 91 列，可以和 分析用 91 列檔案對照。落後的人直接用這個檔案進入模組 2。

    為什麼要排除？那 1 列待查資料（B區 2025-04）陽性數 1,405、篩檢人數 1,285，解答檔中同一列的原值是 61。如果沒有排除它，B區陽性率會飆到約 16%，變成全市最高，結論會完全錯誤。
模組 2｜分析與圖表：找出篩檢陽性率較高的區 23–37 分
🎯 目標：算出各區篩檢陽性率、畫圖，並驗算 AI 的數字、讀懂結果的限制。

  1. 各區篩檢陽性率表＋長條圖

    請在同一個對話繼續。若你新開了對話，Claude 看不到剛才的資料，需要重新上傳「分析用 91 列」檔案。

    請用分析用資料（91 列），做以下分析： 1. 各行政區篩檢陽性率（以納入的月份合計）= 陽性數合計 ÷ 篩檢人數合計（%，小數 2 位），由高到低排序成表格，另附篩檢人數、陽性數合計與「納入月數」 2. 畫一張各區篩檢陽性率長條圖（最高的兩區用醒目顏色） 圖表請有標題、座標軸名稱與單位，並在圖下方用一句話說明重點。 最後說明：這份分析用了幾列、排除了幾列。

    一張排序表＋一張圖；對照下方「預期結果」。H區（9.46%）、E區（8.71%）最高。注意 B區只納入 9 個月、A區與H區 11 個月，其餘 12 個月，所以不是嚴格的「全年」比較。

  2. 要求 Claude 說明怎麼算的

    請列出你剛才計算篩檢陽性率使用的程式碼或公式，以及被排除的列號，讓我可以自己重算。

    看到 Python（pandas）或公式，以及排除列清單。

  3. 人工驗算 1 個數字（必做）

    用計算機或 Excel 驗算：

    • H區：530 ÷ 5,601 ≈ 9.46%
    • 選做：各區篩檢人數加總 = 107,171（全部 91 列合計）
    注意：只要有一個數字對不上，就請 Claude 說明差異原因，直到你能解釋為止，再往下做。

  4. 讀結果前先想：這個數字能說什麼？

    陽性率較高 ≠ 高風險。這是「受檢者」的陽性率，不是全區居民的盛行率；篩檢對象不是隨機抽樣，也沒有做年齡標準化。各區納入的月數不同、分母小的區（如 H區）數字也比較不穩定，不能直接外推。
    更多判讀提醒（點開）
    • 陽性是初篩結果，不等於確診；本資料沒有複檢或確診資訊。
    • 最近 1–2 個月在實務上可能因通報延遲而偏低，要標示「暫定」並註明資料截止日（示範資料沒有模擬這個現象）。
    • 報告建議資源配置時，請「率」和「絕對數」一起呈現。
📚 課後延伸：月趨勢與信賴區間（講師口述 1 分鐘，學員課後做）
請畫全市每月篩檢陽性率折線圖，並為各區篩檢陽性率加上 95% 信賴區間（請說明你用的方法）。 請注意：單月分母較小、各月納入的區數也不同，波動可能很大，請在圖上標示，不要把小波動寫成「上升」或「下降」。 只描述數字，不要推論原因。

方法名稱與假設都有說明。若方法你不熟，追問「為什麼選這個方法」並查證；查方法時只輸入方法名稱，不要把資料貼到網頁搜尋。

怎麼讀信賴區間：兩個區間重疊，並不代表兩者沒有差異；要比較兩區，請看「差異本身」的區間或做檢定。例如 H區與E區的區間有重疊，這份資料的雙比例檢定 p≈0.13，無法確認 H區高於 E區。信賴區間只反映抽樣誤差，不含篩檢對象的選擇偏差，且本課為簡化算法（沒有考慮月別群聚）。

1、2、12 月偏高是示範資料中人為加入的季節因子，用來讓圖表有變化，不是真實現象。

名詞小抄

名詞白話說明
去識別化拿掉能認出是誰的資訊（姓名、證號等）。但資訊組合起來仍可能認出人，所以不等於可以隨意上傳。
小細格表格中人數很少的格子（例如某區某月只有 1 例），容易被推回個人。
篩檢陽性率陽性數 ÷ 篩檢人數。陽性是初篩結果，不等於確診；只代表「有來篩檢的人」，不等於全區居民的盛行率。
信賴區間估計值可能的範圍。兩個區間重疊，不代表兩者沒有差異；要比較兩區，請看差異本身的區間或做檢定。
年齡標準化把各區年齡結構調成一樣再比較，避免年輕或高齡人口多寡造成的差異。
人在迴圈（Human-in-the-loop）重要判斷由人決定，AI 只負責執行與提供選項。
SOP標準作業流程：把做法寫成步驟，下次照做。
pandas常用的 Python 資料處理套件。你不用會寫，只要看得出 Claude 用它算出什麼。
YYYY-MM年-月的寫法，例如 2025-04。
